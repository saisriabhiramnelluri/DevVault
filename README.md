# DevVault

**Security-first platform for developers** to securely store and manage project environments, service accounts, and project setup commands.

> Never lose project secrets, account ownership information, or setup commands again.

---

## Architecture

```
DevVault/
├── frontend/   → Next.js 16 (App Router) — deployed on Vercel
└── backend/    → Express.js 5 + Prisma 7 + PostgreSQL — deployed on Render
```

### Security Model (E2E Encryption)

```
User Password (in browser, never sent to server)
        +
Per-user PBKDF2 Salt (fetched from server, not secret)
        │
        ▼
PBKDF2 (Web Crypto API, 600,000 iterations, SHA-256)
        │
        ▼
AES-256-GCM Key  ← lives only in browser memory
        │
        ▼
encrypt(secret) → { ciphertext, iv }  ← only this is stored in DB
```

- **Zero-knowledge**: The server never sees plaintext secrets
- **Browser-only crypto**: Key derivation and encryption use the native Web Crypto API
- **No third-party crypto deps**: Everything is native browser APIs
- **Forgot password**: Resets vault key → encrypted data is cleared (unavoidable with zero-knowledge)

## Quick Start

### Prerequisites

- Node.js 18+
- PostgreSQL database ([Neon](https://neon.tech), [Supabase](https://supabase.com), or local)
- SMTP credentials (Gmail App Password, Resend, etc.)

### 1. Clone & Setup Backend

```bash
cd backend
cp .env .env.backup   # Save a copy, then edit .env
# Edit .env with your DATABASE_URL, JWT_SECRET, SMTP credentials
npm install
npm run db:generate   # Generates Prisma Client (uses driver adapter)
npm run db:migrate:dev -- --name init   # Creates tables in dev mode
npm run dev
```

The API starts on `http://localhost:5000`. Verify with:
```bash
curl http://localhost:5000/health
# → {"status":"ok","timestamp":"..."}
```

### 2. Setup Frontend

```bash
cd frontend
# Edit .env — set NEXT_PUBLIC_API_URL to your backend URL
npm install
npm run dev
```

The app starts on `http://localhost:3000`.

## Environment Variables

### Backend (`backend/.env`)

| Variable | Required | Description | Example |
|---|---|---|---|
| `PORT` | No | Server port (defaults to `5000`) | `5000` |
| `NODE_ENV` | No | Environment mode (defaults to `development`) | `production` |
| `DATABASE_URL` | **Yes** | PostgreSQL connection string | `postgresql://user:pass@host:5432/devvault` |
| `JWT_SECRET` | **Yes** | Secret for signing JWTs (min 32 chars) | Use `node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"` |
| `JWT_EXPIRES_IN` | No | JWT token lifetime (defaults to `1h`) | `1h`, `30m`, `7d` |
| `FRONTEND_URL` | **Yes** | Frontend URL for CORS whitelist | `https://your-app.vercel.app` |
| `SMTP_HOST` | **Yes** | SMTP server hostname | `smtp.gmail.com` |
| `SMTP_PORT` | No | SMTP server port (defaults to `587`) | `587` or `465` for SSL |
| `SMTP_USER` | **Yes** | SMTP username/email | `you@gmail.com` |
| `SMTP_PASS` | **Yes** | SMTP password / app password | Gmail App Password |
| `SMTP_FROM` | No | Sender address for emails | `DevVault <you@gmail.com>` |
| `OTP_EXPIRES_MINUTES` | No | OTP code expiry (defaults to `5`) | `5` |

### Frontend (`frontend/.env`)

| Variable | Required | Description | Example |
|---|---|---|---|
| `NEXT_PUBLIC_API_URL` | **Yes** | Backend API base URL | `https://devvault-api.onrender.com` |

## Deployment

### Frontend → Vercel

1. Push the repo to GitHub
2. Import the repo in [Vercel](https://vercel.com)
3. Set **Root Directory** to `frontend`
4. Add environment variable: `NEXT_PUBLIC_API_URL` = your Render backend URL (e.g. `https://devvault-api.onrender.com`)
5. Deploy — Vercel will auto-detect Next.js and use the included [`vercel.json`](frontend/vercel.json) config

> **Note**: The `vercel.json` specifies `buildCommand: "npm run build"`, `installCommand: "npm install"`, and `outputDirectory: ".next"`. You generally don't need to change these.

### Backend → Render

#### Option A: Render Blueprint (Recommended)

1. Push the repo to GitHub
2. Go to [Render Dashboard](https://render.com) → **New** → **Blueprint**
3. Connect your repo and set **Root Directory** to `backend`
4. Render will auto-detect the included [`render.yaml`](backend/render.yaml) and create the service
5. Fill in the prompted environment variables (`DATABASE_URL`, `FRONTEND_URL`, `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`)
6. `JWT_SECRET` is auto-generated by the blueprint
7. Deploy

#### Option B: Manual Web Service

1. Push the repo to GitHub
2. Create a **Web Service** in [Render](https://render.com)
3. Set **Root Directory** to `backend`
4. **Build Command**:
   ```
   npm install && npm run db:generate && npm run build && npm run db:migrate
   ```
5. **Start Command**: `npm start`
6. **Health Check Path**: `/health`
7. Add all environment variables listed above
8. Set `FRONTEND_URL` to your Vercel frontend URL
9. Deploy

#### render.yaml Reference

The included blueprint configures:

| Setting | Value |
|---|---|
| Service type | Web Service (Node.js) |
| Region | Oregon |
| Plan | Free |
| Health check | `/health` |
| Build | `npm install && npm run db:generate && npm run build && npm run db:migrate` |
| Start | `npm start` |

### Post-Deployment Checklist

- [ ] Backend `/health` endpoint returns `{"status":"ok"}`
- [ ] `FRONTEND_URL` on Render matches your exact Vercel URL (no trailing slash)
- [ ] `NEXT_PUBLIC_API_URL` on Vercel matches your exact Render URL (no trailing slash)
- [ ] SMTP credentials are valid — test by registering a new account
- [ ] `JWT_SECRET` is a strong, unique value (not the default placeholder)
- [ ] CORS is working — frontend can call backend without `403` errors

### Troubleshooting

| Issue | Cause | Fix |
|---|---|---|
| `CORS error` in browser console | `FRONTEND_URL` doesn't match the actual frontend origin | Set `FRONTEND_URL` to the exact Vercel URL (e.g. `https://devvault.vercel.app`) |
| Prisma migration fails on Render | Database not accessible or `DATABASE_URL` wrong | Verify the connection string; Neon/Supabase URLs must include `?sslmode=require` |
| OTP emails not arriving | SMTP credentials invalid or Gmail blocking | Use a Gmail [App Password](https://support.google.com/accounts/answer/185833), not your regular password |
| `502 Bad Gateway` on Render | App crashed on startup | Check Render logs; usually a missing env var or database connection issue |
| `SESSION_EXPIRED` errors | JWT expired or session revoked | Re-login; check `JWT_EXPIRES_IN` (default `1h`) and `session.expiresHours` (1h) |
| Encrypted data lost after password reset | By design — zero-knowledge encryption | Password reset clears all encrypted vault data; re-enter secrets after reset |

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | Next.js 16.2, React 19.2, TypeScript 5, TailwindCSS 4, Radix UI, Lucide Icons, Framer Motion |
| Backend | Express.js 5.2, TypeScript 6, Prisma ORM 7.8 (with `@prisma/adapter-pg` driver adapter) |
| Database | PostgreSQL (via `pg` driver + Prisma adapter) |
| Auth | bcryptjs (cost 12), JWT, OTP (6-digit, 5-min expiry) |
| Encryption | AES-256-GCM via Web Crypto API, PBKDF2 (600K iterations) |
| Validation | Zod 4 |
| Email | Nodemailer 9 |
| Security | Helmet, CORS, Rate Limiting (express-rate-limit), Session Management |
